## 1. Юридическое и бизнес

| Что | Зачем | Комментарий |
|---|---|---|
| Юр. лицо / ИП | Приём платежей, договоры с провайдерами | От страны регистрации зависит доступность Stripe (для РФ-компаний недоступен) |
| Название продукта и домен | Открытый вопрос в PRD | Домен нужен для сайта, писем, OAuth-редиректов, расширения |
| Пользовательское соглашение (ToS) и политика конфиденциальности | Обязательны для Google OAuth, Chrome Web Store, Stripe | Опишите: какие данные храним (резюме, токены почты/Telegram), сроки, удаление |
| Консультация юриста по персональным данным | GDPR (ЕС), 152-ФЗ (граждане РФ — требование локализации БД в РФ) | Влияет на выбор региона хостинга |
| Оценка рисков автоматизации | Автоматические действия в LinkedIn и с пользовательских Telegram-аккаунтов нарушают/ограничиваются правилами этих платформ | Возможны баны аккаунтов пользователей; нужно честное предупреждение в UI и ToS |
| Финальные цены тарифов | Сейчас Basic $15 / 300 кредитов, Pro $29 / 1000 — дефолты | |
| Налоги | НДС/sales tax по странам | Stripe Tax или merchant of record (Paddle / LemonSqueezy) — решение владельца |

## 2. Инфраструктура

| Компонент | Что нужно | Варианты |
|---|---|---|
| **База, Auth, Storage** | Проект Supabase Cloud (платный план ради бэкапов и PITR) | Регион по итогам юр. консультации; альтернатива — self-hosted Supabase |
| **Веб (Next.js 16)** | Хостинг Node.js | Vercel или Docker-контейнер на VPS |
| **API (FastAPI)** | Хостинг Python-контейнера с HTTPS | Fly.io / Render / Railway / VPS (Hetzner и т. п.) |
| **Воркер Celery + Celery Beat** | Долгоживущие процессы рядом с API | Тот же хостинг, что API; Beat — строго в одном экземпляре |
| **Redis / Valkey** | Брокер очередей, лимиты, блокировки | Managed Redis (Upstash, Redis Cloud) или контейнер Valkey; данные в нём не критичны |
| **Домен, DNS, TLS** | `app.<домен>`, `api.<домен>` | Cloudflare или DNS регистратора; сертификаты — автоматически у хостинга |
| **SMTP для писем Auth** | Подтверждение email и сброс пароля | Встроенный SMTP Supabase — только для тестов (жёсткий лимит). Нужен Resend / Postmark / Amazon SES + записи SPF, DKIM, DMARC |
| **Мониторинг** | Ошибки, логи, аптайм | Sentry (веб + бэкенд), аптайм-проверка `GET /health`, алерты на падение воркера |

Что команда ещё должна сделать к релизу (MR): Dockerfile'ы и прод-сборку, прогон производительности на прод-сборке (TD-005), аудит безопасности, README с пошаговым деплоем.

## 3. Внешние сервисы и ключи

### 3.1 Google (вход через Google — уже в M1; отправка через Gmail — M3)
- Проект в Google Cloud Console → OAuth consent screen → OAuth Client ID (Web).
- Redirect URI: `https://<проект>.supabase.co/auth/v1/callback`; Client ID/secret вписать в Supabase → Auth → Providers → Google.
- Для Gmail нужен scope `gmail.send` (только отправка). Это «чувствительный» scope → **верификация приложения Google** (от нескольких дней до нескольких недель; нужны домен, политика конфиденциальности, демо-видео). Заложите время заранее. Альтернатива для пользователей — подключение по SMTP (пароль приложения).
- Живая проверка входа через Google на реальном аккаунте перед запуском (TD-006).

### 3.2 LLM (Claude по умолчанию)
- Аккаунт Anthropic API, ключ `ANTHROPIC_API_KEY`, лимиты расходов в консоли.
- `LLM_PROVIDER=anthropic`, модели `LLM_MODEL_FAST` / `LLM_MODEL_SMART`.
- Оцените стоимость: разбор резюме + скоринг вакансий + сопроводительные письма на пользователя в день.

### 3.3 Telegram (M3, M5)
- **api_id / api_hash** на my.telegram.org — для подключения Telegram-аккаунтов пользователей (MTProto, Telethon).
- **Бот** через @BotFather — для уведомлений и оплаты Telegram Stars; токен бота и секрет вебхука `/webhooks/telegram`.
- Вывод Stars — через Fragment (в TON), требует отдельной настройки.

### 3.4 LinkedIn (M4) — Chrome-расширение
- Аккаунт разработчика Chrome Web Store (разовый взнос $5), публикация расширения и прохождение ревью.
- Нужны политика конфиденциальности и объяснение каждого разрешения расширения.
- ID расширения и домен приложения прописываются в конфиге (`externally_connectable`).

### 3.5 Платежи (M5)
- **Stripe:** live-аккаунт, продукты и цены (Basic, Pro), секретный ключ, секрет вебхука `/webhooks/stripe`, настройка налогов.
- **USDT:** выбрать провайдера крипто-шлюза (открытое решение владельца, напр. NOWPayments / Cryptomus / CoinPayments) — KYC, ключи API, секрет вебхука `/webhooks/crypto`.
- **Telegram Stars:** через бота из 3.3.

## 4. Секреты и переменные окружения (прод)

| Переменная | Где | Откуда |
|---|---|---|
| `APP_ENV=production` | API, воркер | — |
| `DATABASE_URL`, `SUPABASE_URL`, `SUPABASE_SECRET_KEY` | API, воркер | Supabase → Project Settings |
| `SUPABASE_JWT_SECRET` | API | Только если проект выдаёт HS256-токены |
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Веб | Supabase (публичные, защищены RLS) |
| `API_URL`, `APP_ORIGIN` | Веб | Ваши домены; `APP_ORIGIN` = `site_url` в Supabase Auth |
| `REDIS_URL`, `REDIS_KEY_PREFIX` | API, воркер | Managed Redis |
| `LLM_PROVIDER`, `ANTHROPIC_API_KEY`, `LLM_MODEL_*` | API, воркер | Anthropic |
| `APP_ENCRYPTION_KEYS` | API, воркер | Сгенерировать: 32 случайных байта в base64 (`k1:<ключ>`). **Шифрует токены почты и Telegram пользователей — потеря ключа = все подключения придётся делать заново; утечка = захват аккаунтов.** Хранить в менеджере секретов + резервная копия офлайн |
| Ключ Vault для HMAC email (D5) | Supabase Vault | Создать при деплое миграций; не терять |
| Ключи Google, Telegram, Stripe, крипто-шлюза | API, воркер | Разделы 3.1–3.5 |

Правила: секреты только в переменных окружения хостинга / менеджере секретов, никогда в git; доступ — у минимума людей.

## 5. Деплой базы

1. `supabase link --project-ref <ref>` и `supabase db push` — применить все миграции из `supabase/migrations`.
2. Создать приватный бакет `resumes` (если миграция не создаёт его сама) и проверить, что RLS включён на всех таблицах.
3. Supabase Auth: `site_url`, список разрешённых redirect URL, шаблоны писем из `supabase/templates/`, кастомный SMTP, провайдер Google.
4. Включить ежедневные бэкапы / PITR и один раз проверить восстановление.
