# Screen spec S-010: Matched vacancy feed with score and reasons

_Owner: Designer · 2026-09-27 · Design system: docs/design/design-system/autoapplier/MASTER.md_

## Purpose and entry points

The default landing screen once a search exists (§8): a scored, deduplicated list of vacancies passing the hard filters (PRD: exclude-words, location, min salary when known, sources, age ≤ 30 days), each showing why it matched and how to act on it. Entry points: "Feed" in the sidebar/bottom nav · redirect target after completing the first search (S-007) · "Back to feed" from S-011's apply flow.

## States

**Loading** — 4–6 `Skeleton` cards on first paint; pagination (page 2+) shows a small inline spinner at the list's end instead of full-page skeletons.

**Populated** — cards sorted by score descending; a vacancy collected from multiple sources renders once, its source badge reading "LinkedIn+2" (tooltip lists all: LinkedIn, Telegram @handle, Hirify) and its detail listing every source individually under "Sources."

**Detail open** — full description, extracted contacts (email/Telegram/link, whichever exist — a missing contact type is simply omitted, not shown as "none"), "Open original" (opens the source URL in a new tab, `rel="noopener"`), Not interested, Apply manually.

**Not interested** — clicking removes the card immediately (optimistic) with a `Sonner` toast "Removed from your feed" / "Убрано из ленты" carrying an "Undo" action (≥5s window) before the removal is finalized server-side and it disappears from *all* the user's feeds/searches per the AC — Undo exists for slips, not to contradict "disappears," so once the toast's window elapses the removal is permanent and not reversible from the UI.

**Empty — no vacancies ever matched this search** — §7 empty pattern: icon `Inbox`, "No vacancies match this search yet" / "По этому поиску пока нет вакансий", body "Try widening your filters — a lower salary floor, more locations, or more sources." / "Попробуйте расширить фильтры: снизьте порог зарплаты, добавьте локации или источники.", button "Edit search" → opens S-007's editor for the active search.

**Empty — everything filtered/hidden** (all matches marked Not interested) — same visual pattern, different copy: "You've reviewed everything here" / "Вы просмотрели всё, что здесь было", body "New matches appear as they're found." / "Новые вакансии появятся по мере поступления." — no "Edit search" button here since nothing is wrong with the filters, just nothing new yet.

**Error (feed failed to load)** — §7 page-error pattern, "Try again" retries the same query.

**Pagination / infinite scroll** — 20 items per page (per AC's perf target); loading the next page appends with a bottom-of-list spinner; no layout shift to already-rendered cards.

## Validation messages

Not applicable — this screen has no form input; the only user-entered value (search selection) is a closed `Select`, nothing to validate.

## Responsive behavior (375 / 768 / 1280)

- **375**: single-column cards, full width, 16px gutter. Apply-channel icons and "Apply manually" wrap to their own row below the reasons if the card's width can't fit them inline. Detail opens as a full-screen route (back arrow in place of a Sheet close), matching S-007's editor pattern at this width.
- **768**: cards remain single column (feed content reads better as one focused column than a grid, per MASTER's `--shell-content-max-width`), 24px gutter; detail opens as a 480px right `Sheet`.
- **1280**: same single-column list, capped at `--shell-content-max-width` (1120px) and centered, 32px gutter; detail `Sheet` at 480px, list dims behind it.

## Accessibility

Focus order: page title → search selector → Filters → each card top-to-bottom (title/company → score region → source badge → apply-channel icons → Not interested → Apply manually) → pagination sentinel.

- The score composition (§5.1) is one accessible unit: `aria-label="Match score 87 out of 100, strong match"` / "Совпадение 87 из 100, хорошее совпадение" on the group, so a screen reader doesn't read the number, bar and label as three disconnected things.
- Apply-channel icons each carry `aria-label` naming the channel ("Apply by email" / "Откликнуться по email") — never icon-only with no accessible name.
- "Not interested" removal announces via the toast's `aria-live="polite"` region; keyboard focus after removal moves to the next card in the list (or the empty state if it was the last one) rather than being lost to a removed element.
- Detail `Sheet`/route: heading is the vacancy title (`h2`), traps focus (Sheet mode) and returns focus to the triggering card's title on close.
- "Open original" indicates it opens a new tab in its accessible name ("Open original (opens in new tab)" / "Открыть оригинал (в новой вкладке)") per standard link-target-change guidance.

## Interactions and motion

- Cards mount with no per-item stagger (MASTER §3.7 — one orchestrated moment at a time, not a cascade); pagination appends instantly below the fold.
- Not interested: card collapses/fades over `--duration-base` after the optimistic removal.
- Detail Sheet slides in from the right, `--duration-base`, `--ease-standard`; mobile full-route transition is instant (no slide).
- `prefers-reduced-motion`: card removal and Sheet entry become instant; the score bar's fill still renders at its final width (no animated fill-in) rather than growing from empty.
