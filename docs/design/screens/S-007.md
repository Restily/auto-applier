# Screen spec S-007: Saved job searches with filters

_Owner: Designer · 2026-09-27 · Design system: docs/design/design-system/autoapplier/MASTER.md_

## Purpose and entry points

Let a user define up to 5 named searches (roles/keywords, seniority, location, salary floor, languages, exclude-words, sources, match threshold) that drive S-010's feed. Entry points: "Searches" in the full-shell sidebar/bottom-tab "More" sheet (§8.1) · empty-state CTA on S-010 when the user has no search yet · "Edit search" from a feed card's active-search context.

## States

**Loading** — `Skeleton` cards (3, shaped like the list row) while searches fetch.

**Empty** — §7 pattern: icon `Search`, "No searches yet" / "Пока нет поисков", "Create a search and we'll start matching vacancies for you." / "Создайте поиск, и мы начнём подбирать вакансии.", button "Create search."

**Populated** — up to 5 cards, Active first then Paused, most-recently-edited first within each group.

**At limit (5/5)** — "Create search" button stays enabled but clicking it shows the limit `Alert` inline above the list instead of opening the editor (§Copy `search.limitReached`); existing searches remain fully editable.

**Editor — create, empty** — every field blank except Target titles and Skills-derived keywords, which pre-fill as removable chips from the user's profile (S-003/S-004) if present; threshold defaults to 70.

**Editor — edit** — pre-filled with the saved search's values.

**Editor — validation blocked** — no target title/keyword: inline error under that field, Save disabled state not used (button stays clickable but the attempt is blocked and focus moves to the field) — consistent with S-004's "block on the real problem, not by disabling the button" pattern.

**Editor — saving** — Save button shows a spinner, keeps its width, stays disabled to prevent double-submit.

**Saved** — `Sonner` toast "Search saved" / "Поиск сохранён"; editor closes; list re-fetches (server is the source of truth, per S-004's reload rule).

**Paused** — card visually muted (`--muted-foreground` body text, `Badge` "Paused"), row action reads "Resume." No new applications are prepared for a paused search (S-010's feed still shows previously-surfaced vacancies until the user removes them, but nothing new is added) — communicated via the card's helper line "Not preparing new matches" / "Не подбираем новые вакансии" while paused.

**Deleting** — `AlertDialog` confirm; on confirm, `Sonner` "Search deleted" / "Поиск удалён"; row removed with a fade.

**Error (list failed to load)** — §7 page-error pattern, "Try again."

## Responsive behavior (375 / 768 / 1280)

- **375**: list is single-column full-width cards; editor opens as a full-screen route (not a Sheet — a right-side sheet at this width would leave no room), with a sticky top bar (`[← Back]` title `[Save]`) replacing the in-sheet header/footer. Slider and switches stay full-width, 44px min height.
- **768**: list cards same as mobile but with row actions inline (not requiring the `⋯` menu to reach Pause); editor becomes the `Sheet` (480px, right-anchored) over the list.
- **1280**: list can show 2 cards per row if ≥3 searches exist (CSS grid, `auto-fill`, min 420px per card) to reduce scroll; editor `Sheet` at 480px, page content dims behind it.

## Accessibility

Focus order: page title → Create search → each card top-to-bottom (name → status badge → Pause/Resume → Edit → `⋯` menu) → (editor open) Sheet close → Name → Target titles → Seniority → Remote → Relocation → Countries → Minimum salary (amount → currency → period) → Vacancy languages → Exclude words → Sources checkboxes → Match threshold slider → Cancel → Save.

- Match threshold `Slider` exposes `aria-valuenow`/`aria-valuemin`/`aria-valuemax` and a visible numeric label that updates live (`aria-live="polite"`, debounced to on-release, not every pixel of drag).
- The limit `Alert` is `role="alert"` region, focus moves to it when Create search is blocked.
- Pause/Resume and Delete are real labelled buttons, not icon-only, except the `⋯` overflow which carries `aria-label="More actions"` / "Другие действия".
- Sheet traps focus while open and returns it to the triggering row's Edit button on close (MASTER §9 keyboard-trap exception).

## Interactions and motion

- Editor Sheet slides in from the right, `--duration-base`, `--ease-standard`; full-screen route on mobile is an instant route transition (no slide, avoids motion-sickness on already-heavy nav change).
- Pause/Resume is optimistic: badge and helper text flip immediately, rolled back with an inline error toast if the write fails.
- Delete: card fades + collapses over `--duration-base` after confirm.
- `prefers-reduced-motion`: Sheet appears without the slide (instant), all fades become instant per MASTER §3.7.
