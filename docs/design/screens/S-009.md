# Screen spec S-009: Add a Telegram channel by @name or t.me link

_Owner: Designer · 2026-09-27 · Design system: docs/design/design-system/autoapplier/MASTER.md_

Not a standalone page — this is the "Manage channels…" panel opened from S-007's Sources section (Telegram channels row), using the §5.2 channel add/validate row pattern. This spec covers the panel itself; the AI classification/ingest behavior (backend) is out of scope here.

## Purpose and entry points

Let a user add a public Telegram job channel as a source for their searches by typing its @handle or `t.me/...` link, with immediate feedback on whether it's usable. Entry points: "Manage channels…" link in S-007's editor Sources section · empty state of this same panel reached the first time a user checks "Telegram channels" with none added yet.

## Components

| Area | Component (UI kit) | Variant | Notes |
|---|---|---|---|
| Container | `Dialog` (≥768px) / `Sheet` bottom (375px) | — | Opened over S-007's editor Sheet; on close, S-007's Sources checkbox reflects whatever channels are Added |
| Add row | `Input` + `Button` | §5.2 pattern | Submits on Enter or click; disabled while empty |

## States

**Empty** — panel opens with no rows, just the add input; no §7 empty-state graphic here (this is a utility panel, not a destination page) — the input's own placeholder and helper line ("Add a public channel to use it as a source" / "Добавьте публичный канал, чтобы использовать его как источник") carry that job.

**Typing** — Add button enables once the input is non-empty; format isn't validated client-side beyond non-empty (the server call is the actual check, since "is this a real public channel" can't be known locally).

**Validating** — on submit, a row appears immediately with `outline` `Badge` "Validating…" / "Проверяем…" and a small inline spinner; input clears and re-focuses so the user can queue another add without waiting.

**Added (public channel)** — row's badge flips to `success` "Added" / "Добавлен(а)"; channel is now checked/available under S-007's "Telegram channels" source.

**Rejected — private channel** — the validating row is replaced by an inline error under the *input* (not left as a list row — a rejected attempt isn't a source, so it shouldn't look like one): "This channel is private. Only public channels can be added." / "Этот канал закрытый. Можно добавить только публичные каналы."

**Rejected — not found** — same treatment: "We couldn't find this channel. Check the @name or link." / "Канал не найден. Проверьте @имя или ссылку."

**Rejected — already added** — same treatment, no duplicate row created: "This channel is already added." / "Этот канал уже добавлен."

**Removing** — click Remove → row fades out immediately (no confirm dialog; removing a source is low-stakes and reversible by re-adding).

**Network/server error validating** — row badge flips to `danger` "Couldn't check this channel" / "Не удалось проверить канал" with a small inline "Retry" text-button on the row itself (not a full-page error — one row failing shouldn't block the others).

## Responsive behavior (375 / 768 / 1280)

- **375**: bottom `Sheet`, full width, input+button stack is one row (input flexes, button fixed ~72px) so both stay ≥44px tall without wrapping; list scrolls internally if it exceeds viewport, Done stays pinned at the bottom.
- **768 / 1280**: centered `Dialog`, fixed 480px width, no behavior change beyond width; list area caps at ~320px height with internal scroll if many channels are added.

## Accessibility

Focus order: Dialog/Sheet close (×) → Input → Add → each existing row top-to-bottom (Remove, or Retry when present) → Done.

- The add `Input` has a visible `Label` ("Add a channel" / "Добавить канал") even though a placeholder also shows the format hint — placeholder never substitutes for the label (MASTER §9).
- Rejection messages render as `role="alert"` under the input and move focus back to the input so the user can immediately correct it.
- Each row's status change (Validating → Added, or Validating → replaced by an input error) is announced via an `aria-live="polite"` region wrapping the list, so a screen-reader user doesn't have to re-poll the row.
- Remove/Retry buttons are icon+visible-label or carry `aria-label`; 44×44px hit area, ≥8px between Remove buttons on adjacent rows.

## Interactions and motion

- New row inserts with a `--duration-fast` fade-in, appended to the bottom of the list.
- Validating → Added/rejected transition is a `--duration-fast` cross-fade, no layout jump (the row keeps its height).
- Remove: `--duration-fast` fade-out then the list reflows.
- `prefers-reduced-motion`: all transitions instant.
