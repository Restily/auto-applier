# Screen spec S-011: Manual apply with an AI cover letter

_Owner: Designer · 2026-09-27 · Design system: docs/design/design-system/autoapplier/MASTER.md_

## Purpose and entry points

Generate an editable, AI-personalized cover letter in the vacancy's language for a user who wants to apply themselves rather than let the product send it — no credits spent (manual apply is free per the PRD). Entry points: "Apply manually" on a S-010 feed card · "Apply manually" in the S-010 detail panel.

## Components

| Area | Component (UI kit) | Variant | Notes |
|---|---|---|---|
| Container | `Dialog` (≥768px) / `Sheet` bottom, full-height (375px) | — | Opened from S-010 |
| Loading | `Progress` (indeterminate) + status text | — | Same long-running pattern as resume extraction (MASTER §7), scaled to a ≤20s wait |
| Letter | `Textarea` | — | Auto-grow to a max height then internal scroll; pre-filled, fully editable, `dir` follows the letter's language |
| Copy | `Button` (`outline`) | — | Copies current (possibly edited) textarea contents |
| Daily counter | small text, `--font-mono` number | — | "{n}/30 today" — visible whenever the letter is loaded, not just near the limit |
| Open original | `Button` (`outline`) | — | Opens the vacancy's original URL in a new tab, `rel="noopener"` |
| I applied | `Button` (`default`) | — | Primary action once a letter exists |
| Cancel / Close | `Button` (`ghost`) / Dialog `×` | — | Discards nothing server-side — no letter was recorded until "I applied" |
| Limit reached | `Alert` `warning` | — | Replaces the generate/loading area entirely, in place of a letter |
| Generation failed | `Alert` `danger` + `Button` "Retry" | — | Replaces the loading area |

## States

**Opening / loading** — Dialog opens immediately with the indeterminate `Progress` + rotating status text ("Reading the vacancy…" → "Writing your cover letter…" → "Almost done…" / "Изучаем вакансию…" → "Пишем сопроводительное письмо…" → "Почти готово…"), each phase holding ~5–7s so three phases fit inside the 20s budget. "This can take up to 20 seconds" / "Это может занять до 20 секунд" shown up front, matching MASTER's "name the wait" rule. No credits are spent to reach this state or by generating — nothing in this screen ever mentions credits, by design (manual apply is explicitly free, so the credit balance in the header is simply irrelevant here, not zeroed-out or hidden).

**Loaded** — editable `Textarea` pre-filled with the generated letter in the vacancy's language (RTL/LTR follows that language, not the UI language), Copy button, daily counter, Open original, Cancel, I applied. Editing the textarea does not trigger regeneration or affect the daily counter — the counter counts generations, not edits.

**Copied** — clicking Copy copies the textarea's current text to the clipboard and shows a brief inline confirmation next to the button ("Copied" / "Скопировано", `--duration-fast` fade, ~2s) rather than a toast (keeps the letter itself the visual focus).

**I applied — confirming** — button shows a spinner, stays disabled to prevent double-submit; on success the Dialog closes, a `Sonner` toast confirms ("Marked as applied" / "Отмечено как «откликнулись»"), and the vacancy leaves the S-010 feed (per AC) the same optimistic way S-010's "Not interested" does.

**Daily limit reached (30/30)** — opening this flow (or hitting the limit mid-session on a second vacancy) shows the `Alert` in place of the generate/loading area: "You've generated 30 cover letters today" / "Сегодня вы уже сгенерировали 30 писем", body naming when it resets: "Try again tomorrow." / "Попробуйте завтра." — no Retry, no letter, Open original still available so the user isn't blocked from applying by hand entirely, just from AI generation for the rest of the day. I applied is **not** offered in this state (no letter exists to have sent) — the user can still mark it applied later from their history if they wrote their own letter, which is out of this screen's scope.

**Generation failed (AI provider error)** — replaces the loading area with the `Alert` `danger`: "Couldn't generate a cover letter" / "Не удалось сгенерировать письмо", body "Something went wrong on our end. Nothing was recorded." / "Что-то пошло не так с нашей стороны. Ничего не записано.", button "Retry" that re-attempts generation (does **not** count twice against the 30/day budget if the failed attempt never completed — the counter only increments on a successful generation). Cancel remains available.

## Validation messages

No user-entered form fields beyond the free-text letter itself, which has no format constraint (the user may edit it to anything, including emptying it — "I applied" stays enabled even on an emptied textarea, since the letter shown here is a convenience, not a submission the product itself sends). The two blocking conditions are system states, not field errors:

| Condition | EN | RU |
|---|---|---|
| 30/30 letters generated today | You've generated 30 cover letters today. Try again tomorrow. | Сегодня вы уже сгенерировали 30 писем. Попробуйте завтра. |
| AI provider failure | Couldn't generate a cover letter. Something went wrong on our end. Nothing was recorded. | Не удалось сгенерировать письмо. Что-то пошло не так с нашей стороны. Ничего не записано. |

## Responsive behavior (375 / 768 / 1280)

- **375**: bottom `Sheet`, full height minus a small top reveal (so the triggering feed card stays contextually "underneath"); Textarea takes remaining vertical space with internal scroll; Copy + counter stack as one row above the fixed-bottom action row (Cancel / I applied), Open original sits directly above that row full-width.
- **768**: centered `Dialog`, 560px wide, height capped at 80vh with the Textarea scrolling internally past that; actions stay in the dialog footer, not fixed.
- **1280**: same 560px `Dialog`, no further layout change — this content never needs the extra width, so it does not grow past 560px even at wide viewports (matches MASTER's "content dictates width, not viewport" default for dialogs).

## Accessibility

Focus order: Dialog close (×) → (loaded) Textarea → Copy → Open original → Cancel → I applied.

- On open, focus moves to the Dialog's heading first (announces the vacancy being applied to) then, once loaded, a `aria-live="polite"` announcement fires once ("Cover letter ready" / "Письмо готово") without stealing focus from wherever the user's attention naturally lands next (they typically start reading the Textarea).
- The rotating loading status text is in an `aria-live="polite"` region, updated per phase (not per second) so it isn't chatty.
- Copy's confirmation ("Copied") is `aria-live="polite"`, not a focus-stealing toast.
- The daily counter is plain text in normal reading order, not decorative-only — a screen reader encounters "12/30 today" / "12/30 сегодня" as part of the page, not via a title attribute.
- Limit and failure `Alert`s are `role="alert"`, and on generation failure focus moves to the Retry button (the most likely next action) rather than staying on a spinner that no longer exists.
- Textarea has a visible `Label` ("Cover letter" / "Сопроводительное письмо") even though the Dialog title already names the context — the field itself is still independently labeled per MASTER §9.

## Interactions and motion

- Dialog/Sheet opens with the standard `--duration-base` entrance (MASTER §3.6/§3.7); loading phase text cross-fades between phases over `--duration-fast`, no bouncing/looping icon.
- Copy confirmation: `--duration-fast` fade in, holds ~2s, fades out — button label itself doesn't change (avoids layout shift from "Copy" → "Copied" changing width); confirmation renders as a small adjacent text instead.
- I applied: button spinner replaces label on click (component default, MASTER §5), Dialog closes with the standard exit transition once the write succeeds.
- `prefers-reduced-motion`: entrance/exit instant; loading phase text still updates (content, not motion) but any progress-bar animation becomes a static filled state per MASTER §7.
