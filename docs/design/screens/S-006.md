# Screen spec S-006: Export my data and delete my account

_Owner: Designer · 2026-09-27 · Design system: docs/design/design-system/autoapplier/MASTER.md_

Detailed spec for the **Your data** and **Danger zone** cards positioned on the Settings screen (S-005 §Layout) — read S-005 first for where these sit on the page; this file is authoritative for their states, copy and the delete-confirmation dialog/screen.

## Purpose and entry points

Give the user full, unambiguous control over their own data: a complete export on demand, and a real, permanent delete that actually removes everything (profile, resume file, searches, connections, stored secrets) rather than a soft "deactivate." This is a trust-critical surface for a product that already asks people to connect real accounts — it has to be exactly as capable as it claims, with no dark patterns slowing down the delete path. Entry points: Settings → Your data card / Danger zone card (S-005 §Layout).

### 6d Accessibility

- `h1` receives programmatic focus on plain arrival (no hash), matching the design system's post-redirect/landing pattern; with a `#after-deletion` hash, focus goes to that section instead (see States above) — never both.
- The placeholder notice is `role="status"` (informational, not an error) so assistive tech announces it without interrupting.
- The `after-deletion` `h2` has an explicit `id`; the section is `aria-labelledby` that id, so it's announced as a named region when reached by focus or landmark navigation.
- Contrast: placeholder-notice text and icon use `--muted-foreground` (7.6:1, MASTER §2.1) on `--surface`; body copy uses `--foreground` at the standard 8.5:1+.

## States

### Export (6a)
- **Idle**: "Download my data" enabled.
- **Preparing** (loading): button shows spinner only (`aria-label` "Preparing your data…" / "Готовим ваши данные…"), stays disabled; typically near-instant for one user's data at MVP scale, but always shown so a slower response never looks stuck.
- **Success**: the browser's native file-download UI takes over (file `autoapplier-export-<YYYY-MM-DD>.json`); our UI shows a toast "Your export is downloading" the moment the response starts, button returns to Idle. We don't (can't, reliably) detect the browser-side save completing, so the toast describes the download starting, not finishing.
- **Error**: toast (danger) "We couldn't prepare your export. Try again," button returns to Idle, nothing partial is left anywhere.

### Delete (6b)
- **Closed**: default; nothing about the Danger zone card implies anything is already in progress.
- **Open, unconfirmed**: dialog as drawn, "Delete my account" disabled — this is the default the moment the dialog opens, never pre-enabled.
- **Typing, not yet matching**: hint text appears under the input ("Doesn't match your account email yet" / "Пока не совпадает с email вашего аккаунта"), button stays disabled. This is informational, not an error — no `--danger` styling, no icon, so a user mid-keystroke never sees a false "wrong" signal.
- **Matches**: "Delete my account" becomes enabled the instant the trimmed, case-insensitive comparison passes — no separate "verify" step.
- **Cancel** (AC3): closes the dialog immediately, input is discarded, nothing is sent to the server, nothing about the account changes. Same result whether triggered by the Cancel button, Escape, or clicking outside (all equally "I changed my mind").
- **Deleting** (confirmed, in flight): "Delete my account" shows its spinner state, both buttons disabled, dialog cannot be dismissed by Escape/outside-click while this is running (the one legitimate use of a focus-trapping, non-dismissible dialog in this product — MASTER §9 calls this out as the correct exception, not a violation, of "no keyboard traps").
- **Success**: session is cleared, browser navigates to 6c (post-deletion screen) — not back to Sign in, since there's a specific, honest thing to say ("deleted," not "signed out").
- **Error** (deletion failed server-side): dialog stays open, re-enables both buttons, shows an inline `Alert` (danger) inside the dialog above the buttons: "We couldn't delete your account. Try again, or contact support if this keeps happening." — the typed email stays in the field (don't make them retype it), nothing about the account is assumed deleted.

## Validation messages

| Condition | EN | RU |
|---|---|---|
| Typed email doesn't match yet (live hint, not submit-time error) | Doesn't match your account email yet | Пока не совпадает с email вашего аккаунта |

There is no submit-time validation error for this field by design — the button simply stays disabled until the comparison passes, so there's nothing to reject on click.

## Responsive behavior (375 / 768 / 1280)

- Export: identical single button at every width.
- Delete dialog: `AlertDialog` on desktop/tablet is a centered modal (~420px); at 375px it becomes a bottom `Sheet`-style full-width panel (standard shadcn responsive dialog pattern) so the confirm-email input and both buttons stay comfortably reachable with one thumb — buttons stack full-width (Cancel above Delete, matching MASTER's "the fix is safer, so it's visually first" convention, same as the empty-state "Clear filters" pattern in MASTER §7) rather than sitting side by side at a cramped width.
- Post-deletion screen: same centered-content focus-shell pattern as S-001 at every width, single line of body text never wraps awkwardly (verified short in both languages).

## Accessibility

- Delete button on the Settings card is reachable in the same focus order as S-005 describes (end of the Danger zone card).
- `AlertDialog` traps focus on open (standard behavior), first focus lands on the confirm-email `Input` (not on either button — typing is the very next thing the user needs to do), returns focus to the "Delete account" card button on Cancel/close.
- The dialog's heading and body are read by the `AlertDialog`'s own `aria-labelledby`/`aria-describedby` wiring the moment it opens, so a screen-reader user hears the irreversibility warning before anything else. `aria-describedby` spans the body paragraph and the fingerprint disclosure (D5) as one description; the disclosure's "Privacy policy" link is announced as a link within it, not raised to a heading, so it doesn't compete with the irreversibility warning for attention.
- The fingerprint-disclosure link (`target="_blank" rel="noopener noreferrer"`, D5) is announced by screen readers as opening in a new tab (native browser/AT behavior for `target="_blank"` needs no extra `aria-label`); focus stays in the dialog, so leaving to read it doesn't lose the typed confirm-email value.
- Post-deletion fingerprint note (D5): plain text + link below the CTA, not `aria-live` — it's static content present on load, not an update to announce.
- The live match hint is `aria-live="polite"` but only announces on its own appear/disappear transition, not on every keystroke in between (avoid a screen reader re-reading "doesn't match yet" after every character).
- The in-dialog delete-error `Alert` is `role="alert"` and receives focus the same way S-001's form-level errors do.
- Post-deletion screen: its `h1` receives programmatic focus on arrival, same pattern as every other post-redirect landing in this design system (S-001, S-002).
- Contrast: destructive button and dialog warning icon use `--danger`/`--on-danger` (5.9:1, MASTER §2.1); the match-hint text uses `--muted-foreground` (7.6:1), not the lighter `--disabled-foreground`, since it's informational, not inactive.

## Interactions and motion

- Dialog open/close: standard shadcn `AlertDialog` motion (`--duration-base`, `--ease-standard`), disabled entirely (instant show/hide) under `prefers-reduced-motion`.
- Match hint: `--duration-fast` fade in/out as the comparison flips, not on every keystroke while it stays in the same (mis)matched state.
- Confirm button enabling: an instant state change the moment the strings match — no debounce delay, since delaying feedback here would read as lag (MASTER §3.7 / Touch & Interaction priority), not caution.
- Post-deletion screen: no entrance animation — it's the last thing this session renders; keep it calm and immediate rather than choreographed.
