# Screen spec S-003: Resume upload → AI-extracted profile

_Owner: Designer · 2026-09-27 · Design system: docs/design/design-system/autoapplier/MASTER.md_

Owns the **Profile Editor** layout that S-004 (manual fill) also uses — S-004 only adds the manual entry point, the Application-answers section, and the persistence/validation behavior for editing after save. Read this file first for the shared structure.

## Purpose and entry points

Turn a resume file into a structured, editable profile in under 60 seconds, or fail safely into a manual form without losing the file. Entry points: the "Upload your resume" step of the Onboarding checklist (S-001 §Onboarding checklist, first-run) · "Replace resume" action inside the Profile Editor (returning user, S-004).

## States

**Upload step**: idle → drag-over (border switches to `--primary`, `--primary-subtle` fill) → file accepted (moves to 3b) → **rejected** (wrong type or >5MB): dropzone gets a `--danger` border for `--duration-fast`, inline message appears below it (Validation table), nothing is sent to the server, dropzone returns to idle after the message is dismissed or a new file is dropped.

**Extraction**: in-progress (3b, up to 60s) → **success** (3d, banner shown) or **failure** (3c). Failure keeps the file attached (AC3) — the Profile Editor still opens, blank, with the Resume file reference visible and "Try again" available from within it too (not just the failure panel), so a user who clicks "Fill manually" isn't stuck if they change their mind.

**Profile Editor — Loading**: while fetching an existing profile (returning user), section `Card`s render as `Skeleton` blocks matching their shape, not a spinner.

**Profile Editor — Empty (manual start, no resume)**: see S-004 — every field starts blank, required-field markers visible from the start.

**Profile Editor — Saving**: Save changes button shows its spinner state (MASTER Button loading), rest of the form stays interactive (not blocked) except a second click on Save is prevented.

**Profile Editor — Field errors**: see S-004 Validation (shared).

**Replace resume**: click → same upload UI reopens (3a) inside a `Dialog` rather than navigating away from the editor → on successful re-extraction, if any field differs from the current profile, show 3e before anything is written; if every field is identical, apply silently (no dialog, since there's nothing to choose).

**Access to the file itself** (AC5, another user/anonymous request): enforced by signed, authenticated, per-user URLs on the backend (RLS/storage policy) — there is no UI state to design because there is no UI path that could expose another user's file (resume links are never public URLs). Flagged here so backend-dev/security treat it as a contract, not a gap in this spec.

| Condition | EN | RU |

| (Required-field validation for the editor itself is shared with S-004 — see that spec.) | | |

File-type/size checks run client-side before any upload request, and are re-checked server-side (never trust the client alone) — if the server rejects a file the client accepted (edge case, e.g. a spoofed extension), show the same messages in the same place.

## Responsive behavior (375 / 768 / 1280)

- Upload step: dropzone is full-width at every size; step dots shrink to unlabeled dots <768px (the words "Sign up / Resume / Profile" don't fit reliably in RU at 375px — see MASTER §3.3 rule 4).
- Extraction progress and failure panels: same single-column card at every width, text wraps naturally (no truncation risk, these are short fixed strings).
- Profile Editor: single column at all three widths (1280/768/375) — this form was never multi-column, so there's no reflow breakpoint to get wrong. What changes: side padding (32/24/16px per MASTER §3.4), and the Save changes bar switches from inline-at-end-of-form (desktop, where the page scrolls past it naturally) to a sticky full-width bottom bar starting at 768px and below, so it's reachable without scrolling back up through a long profile.
- Chip inputs (Target titles, Skills) wrap to multiple lines rather than scrolling horizontally at any width.
- Nested entry rows (Experience/Education/Language): Edit/Remove actions stay as visible icon buttons ≥44px at 375px (not hidden behind a hover-only affordance — this is a touch-first requirement, not just mobile-specific).

## Accessibility

**Focus order (Profile Editor)**: skip link → shell header/nav (MASTER §8.6) → "Replace resume" (if present) → banner's dismiss control (if present) → each section in visual order, within a section: label→field pairs top to bottom, entry rows' Edit then Remove → "+ Add …" button → next section → Save changes (also reachable via the sticky bar without needing to scroll, since it's `position: sticky`, still in normal tab order once reached).

- Dropzone is keyboard-operable as a button (Enter/Space opens the native file picker), not only a mouse drag target; it has a visible focus ring and an accessible name that states the constraint ("Upload your resume, PDF or DOCX, up to 5 megabytes").
- Extraction status text updates announce via `aria-live="polite"` (not `assertive` — it's progress, not an alert) so a screen-reader user hears each phase without the announcement interrupting anything.
- Chip/combobox fields (Target titles, Skills): standard combobox ARIA pattern (`role="combobox"`, `aria-expanded`, listbox of options), each chip's remove button individually labeled ("Remove Playwright"), arrow-key navigation within the option list.
- Add/Edit entry `Dialog`s trap focus while open, return focus to the row's Edit button (or the "+ Add" button, for a new entry) on close.
- The review-changes dialog (3e)'s radio groups are properly grouped with a `fieldset`/`legend` per field row, so "Keep current / Use new" is announced with the field name, not just "radio button 1 of 2."
- Required-field asterisks are paired with `aria-required="true"`, not conveyed by the asterisk glyph alone.
- Contrast: section `Card` borders (`--border`), field `input-border` (3.6:1), all text per MASTER §2.1 — the success-toned banner text/icon uses `--success` (5.1:1) paired with the `CheckCircle2` icon and the word "filled," never color alone.

## Interactions and motion

- Drag-over: dropzone border/fill transition over `--duration-fast`.
- File accepted → progress panel: `--duration-base` cross-fade (3a → 3b in place, not a route change).
- Extraction status line: text changes are a straight content swap (no slide/fade per line — only the panel-level transitions animate, to avoid the "everything animates" anti-pattern).
- Extraction failure/success: `--duration-base` cross-fade into 3c or 3d.
- Adding/removing a chip: chip enters with a `--duration-fast` scale+fade, removal is instant removal from layout after a `--duration-fast` fade-out (so the row reflow doesn't feel like a snap).
- Entry `Dialog` open/close: standard shadcn `Dialog` motion (`--duration-base`, `--ease-standard`).
- Save changes → success: toast "Saved" (`Sonner`, MASTER §5), button returns to its default label; no full-page reload.
- All of the above collapse to instant state changes under `prefers-reduced-motion`.
