# Screen spec S-012: Operator back office — sources, channel catalog, health

_Owner: Designer · 2026-09-27 · Design system: docs/design/design-system/autoapplier/MASTER.md_

## Purpose and entry points

Give operator-role users visibility into every ingestion source's health and let them curate the public Telegram channel catalog, without exposing this to ordinary users. Entry points: "Back office" nav item (bottom of sidebar, below a divider, operator accounts only — §8.1) · "Back office" entry in the account `DropdownMenu` (§8.4) · a direct URL hit by a non-operator, handled by the Access denied state.

## States

**Loading** — `Skeleton` rows (6) matching the table's column widths.

**Populated** — every source (structural: LinkedIn, Hirify/HireHi; catalog: each added Telegram channel) as one row, sorted by Status (Needs attention first) then Last fetch ascending (staler first) — surfacing problems is this screen's whole job, so the default sort leads with them rather than alphabetically.

**Row: healthy** — last successful fetch ≤ 2h ago. `CheckCircle2` icon (`--success`) in the first cell, `Badge` "Healthy" (`success`), neutral `--border` left accent, no `⚠`.

**Row: needs attention** — no successful fetch in > 2h (AC's exact threshold). `AlertTriangle` icon (`--warning`) in the first cell, `Badge` "Needs attention" (`warning`), 2px `--warning` left border accent, "Last fetch" cell also carries the `⚠` glyph next to the timestamp as a third redundant signal (§5.3).

**Row: catalog channel, disabled** — row is present but visually muted (`--muted-foreground` text throughout, `Badge` swaps to `neutral` "Disabled" / "Отключён"), action button reads "Enable"; it is excluded from fetching (AC) and therefore never shows stale-row styling even if its last fetch is old — "disabled" and "needs attention" are mutually exclusive states, never combined.

**Toggling disable/enable** — optimistic: row's action button shows a spinner briefly, badge/muting flips immediately; on failure the row reverts with an inline `Sonner` error toast ("Couldn't update this channel" / "Не удалось обновить канал").

**Add channel — validating/added/rejected** — identical states to §5.2/S-009, scoped to the shared catalog rather than one user's sources; a successfully added channel appears in the back-office table immediately on "Done" (optimistic insert, reconciled on next table refresh).

**Empty (no sources at all)** — theoretical/pre-seed only; §7 pattern, icon `ServerOff`, "No sources yet" / "Пока нет источников", body "Add a Telegram channel to start ingesting vacancies." / "Добавьте канал в Telegram, чтобы начать сбор вакансий.", button "Add channel."

**Error (table failed to load)** — §7 page-error pattern, "Try again."

**Access denied** — a non-operator who reaches the route (direct link, stale bookmark) sees this in place of the table: icon `Lock` (24px, `--muted-foreground`, `--surface-sunken` circle — deliberately neutral, not `--danger`, since this isn't the user's error), heading "Access denied" / "Доступ запрещён", body "This page is for operators only." / "Эта страница доступна только операторам.", button "Back to feed" / "Вернуться в ленту." This is a UI courtesy only — the real boundary is the backend role/RLS check (MASTER §8.1); the same copy and layout apply if an authenticated non-operator's API calls return 403, surfaced via the page-level error state rather than a silent redirect (silent redirects hide *why* nothing loaded).

## Validation messages

Channel-add validation is identical to S-009 (§Validation messages there — private channel, not found, already added). No other form input on this screen; Disable/Enable is a binary toggle with no invalid state.

## Responsive behavior (375 / 768 / 1280)

- **375**: table collapses to stacked cards, one per source — each card shows Source name + Type badge on the top line, Status badge + icon on the next, Last fetch / 24h / Errors as a small label:value grid below, Disable/Enable full-width at the card's bottom if present. This mirrors S-007's card-list treatment rather than a horizontally-scrolling table, since an operator on mobile is checking status, not doing dense comparison.
- **768**: real `Table` returns, with Type and Errors columns collapsing into a `Tooltip`/expandable secondary line under Source to fit the width (Last fetch, 24h, Status, action stay as columns); horizontal scroll is the fallback only if content still overflows, never the first choice.
- **1280**: full table as drawn in §Layout, all seven columns visible, `--shell-content-max-width` applies.

## Accessibility

Focus order: page title → Add channel → table column headers (sortable ones are buttons) → each row left to right (Source → Type → Last fetch → 24h → Errors → Status → action button) top to bottom.

- Sortable headers (Source, Last fetch) are `button`s with `aria-sort` ("ascending"/"descending"/"none").
- Each stale row's `⚠` icon carries `aria-hidden="true"` (decorative — the redundancy is already in the Badge text and border, not the icon's meaning) except the Status-column icon pairing, which is part of the Badge's accessible name.
- Errors-cell `Tooltip` content is also reachable via keyboard focus (not hover-only) and exposed via `aria-describedby`, so the error detail isn't mouse-only.
- Disable/Enable buttons have accessible names that include the channel ("Disable @frontend_eu" / "Отключить @frontend_eu") so a screen-reader user tabbing through many rows doesn't hear a run of identical "Disable" buttons.
- Access denied page: heading is a real `h1`, button receives initial focus (there's nothing else useful to interact with on this page).

## Interactions and motion

- Row status toggle: `--duration-fast` cross-fade between enabled/disabled visual treatment.
- New catalog row (after Add channel → Done): inserts with the same `--duration-fast` fade as S-009/S-010 list insertions, re-sorted into place on the next natural refresh rather than jumping immediately (avoids a newly-healthy-looking row visually fighting the stale-first sort before it has any fetch history).
- `prefers-reduced-motion`: all transitions instant, consistent with the rest of the system.
